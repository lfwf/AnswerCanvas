# AnswerCanvas 重播后暂停设计

## 目标

保留场景首次打开后的自动播放行为。用户点击“重播”时，将所有动态书写进度归零并停在时间轴开头；只有再次点击“继续”才开始播放。

## 状态转换

- 首次加载完成：`idle → playing`，行为不变。
- 播放中点击暂停：`playing → paused`，保留当前位置。
- 任意可操作状态点击重播：清零全部动态进度并进入 `paused`。
- 重播后点击继续：`paused → playing`，从第一个动态元素开始。
- 播放完成后点击重播：`complete → paused`，允许重新开始。
- 减少动态效果模式：仍直接显示完成态，重播按钮禁用且重播处理为 no-op，动态内容不得被隐藏或重新执行路径动画。

静态场景元素始终以完成态渲染，不受重播清零影响。

## 实现

在 `RecreationPlayer` 中增加 `reset()`：取消当前动画帧、把内部状态明确设为 `paused`、重置索引、已用时间和完成回调标记，并向所有事件发送进度 `0`，但不播放或调度新帧。已取消或迟到的动画帧因状态不是 `playing` 而不得继续推进。现有 `replay()` 复用 `reset()` 后继续调用 `play()`，以保持现有播放器 API 语义。

`RecreationStage` 的重播按钮改为先取消尚未触发的首次自动播放定时器，再调用 `reset()`、清空 React 进度并把状态设为 `paused`。主按钮随后显示“继续”，点击后调用 `resume()`。组件增加可观察的播放器就绪状态；播放、重播与速度控件只有在播放器完成初始化后才可操作，避免字体已就绪但 effect 尚未创建播放器时出现可点击的空操作。

## 验收

- 播放器 `reset()` 清零进度且不请求动画帧。
- reset 后 resume 从第一个事件开始。
- reset 后播放器状态为 `paused`，迟到的旧帧不能推进进度。
- reset 会重新允许完成回调在下一轮播放结束时恰好触发一次；旧 `replay()` 仍保持“清零并立即播放”。
- 点击重播后界面显示“继续”和“已暂停”。
- 在首次自动播放开始前点击重播，也必须保持暂停，待执行的自动播放不得重新启动。
- 播放过程中点击重播必须回到开头并暂停。
- 首次加载仍自动播放。
- 播放完成后仍可重播到暂停状态。
- 播放器初始化前控件禁用；初始化完成后才允许操作。
- 减少动态效果模式下重播禁用，动态内容始终完整可见且不播放路径动画。
- Stage 级测试确认重播仅清空动态元素，静态元素继续以完成态显示。
- 全量测试、ESLint 和生产构建通过。
