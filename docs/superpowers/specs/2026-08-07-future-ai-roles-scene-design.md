# AnswerCanvas「未来 3 年最需要 AI 能力的岗位」场景设计

## 1. 目标

将用户提供的竖版知识卡片新增为第三个可播放手写场景。场景重点复刻原图的四区版式、信息层级、图标语义、彩色强调与自然书写过程；正文允许适度压缩，但必须保留六类岗位、四项岗位特征、五项值钱能力、AI 协作流程和岗位价值矩阵。

新场景不得覆盖或修改 `skill-agent-notes`、`ai-core-concepts` 的场景数据。

## 2. 场景身份与画布

- 规范 ID：`future-ai-roles`
- 标题：`未来 3 年，最需要 AI 能力的岗位`
- 逻辑尺寸：`1125 × 1432`，保持参考图纵向比例
- 纸张：暖白色 `plain` 背景，使用现有纸张纹理，不把参考图作为背景
- 渲染：HTML 文字与 SVG 路径混合，复用 `RecreationCanvas` 和 `RecreationStage`

## 3. 页面结构

### 3.1 顶部

- 居中主标题，黑色粗手写字
- 标题下方红色长下划线
- 一行“核心判断”，保留信息处理、内容生成、流程协作三个红色波浪强调

### 3.2 左上：最需要 AI 能力的岗位

保留六类岗位，每类先绘制语义图标，再书写岗位名称与说明：

1. 软件开发 / 测试：代码、调试、文档、自动化测试
2. 产品经理 / 运营：方案、分析、拆需求、复盘优化
3. 数据分析 / 财务：数据清洗、报表、预测、异常发现
4. 设计 / 内容创作：文案、海报、视频脚本、素材生成
5. 销售 / 客服 / HR：话术、客户分类、简历筛选、知识问答
6. 制造 / 供应链 / 流程岗位：流程自动化、异常排查、排产协同、知识沉淀

图标分别使用电脑、清单、图表、调色盘、耳机和工厂/货车的手绘 SVG。

### 3.3 右上：为什么是这些岗位

- 四条原因：信息量大、重复任务多、需要快速产出、依赖跨部门协作
- 流程图：信息输入 → AI 处理 → 人判断 → 输出结果
- 信息漏斗及四个流程框使用蓝、绿、橙、蓝描边

### 3.4 左下：岗位里最值钱的 AI 能力

保留五项能力，每项先绘制图标，再书写文字：

1. 会提问（Prompt）
2. 会用 AI 工具
3. 会验证结果
4. 会整合工作流
5. 会把 AI 变成效率

图标分别使用问号气泡、工具、检查板、流程节点和上升图表。

### 3.5 右下：结论与价值矩阵

- 黄色手绘圆角结论框，保留“大多数白领岗位都会被会不会用 AI 拉开差距”的核心结论
- 二维矩阵：横轴为 AI 使用能力，纵轴为岗位价值
- 四象限保留专业强/弱与会用/不会用 AI 的组合
- 高价值象限使用红色星形强调
- 右侧公式：高价值岗位 = 专业能力 × AI 能力

## 4. 动画与单笔约束

总体顺序为：标题与核心判断 → 左上 → 右上 → 左下 → 右下。

每个内容组内部必须先绘制图标，再书写对应文字。动态元素使用唯一、非负、递增的 `order`；不允许两个动态元素并发。页面的主要横向、纵向分隔线为静态元素，不进入时间轴。标题、图标、文字、下划线、结论框和矩阵内容均为动态元素。

## 5. 实现边界

- 新增 `features/recreation/scenes/future-ai-roles.ts`
- 新增 `features/recreation/scenes/future-ai-roles.test.ts`
- 仅在 `features/recreation/scenes/index.ts` 注册一次
- 不在公共画布或播放器中添加场景 ID 条件
- 如果现有 primitive 足够，不扩展共享协议或新增图标组件库

## 6. 验收

- 画廊出现第三张场景卡片，旧场景仍保留
- `/scenes/future-ai-roles` 可直接打开
- 场景尺寸、纸张配置与参考图比例匹配
- 四个内容区域、六类岗位、四项原因、五项能力、流程图、结论框和价值矩阵齐全
- 每组图标的动画顺序早于对应文字
- 静态分隔线不参与重播清空
- 场景校验无重复 ID、重复 order、越界文字或非法标注目标
- 单元测试、ESLint 和生产构建通过
